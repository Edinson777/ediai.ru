# MAX ⇄ GLM чат-бот для AdminVPS (PHP + MySQL)

Версия чат-бота для мессенджера **MAX** на **PHP + MySQL** — под виртуальный хостинг [AdminVPS](https://adminvps.ru) (и любой другой хостинг с PHP и MySQL). Бот пересылает сообщения пользователей в модель **GLM (Z.ai)** и возвращает ответы. Логика идентична Node-версии (`max-glm-bot`), внешние зависимости не нужны — только cURL и PDO MySQL, которые на AdminVPS включены по умолчанию.

## Возможности

- **Память диалога в MySQL** — бот помнит последние сообщения каждого чата (по умолчанию 12), команда `/reset` очищает.
- **Webhook** — MAX сам присылает события на `https://ваш-домен/…/index.php` (нужен SSL — на AdminVPS бесплатный Let's Encrypt).
- **Режим cron-polling** — альтернатива без домена: cron запускает `run.php --once` каждую минуту, бот сам опрашивает MAX.
- **Белый список чатов** — только выбранные `chat_id`; «чужой» диалог сам получит сообщение со своим ID.
- **Команды** `/start`, `/reset`, `/stats`, `/help` — регистрируются в меню бота.
- **Логи и учёт токенов** — каждый запрос к GLM логируется с расходом prompt/completion-токенов; `/stats` показывает итог за день (хранится в MySQL).
- **Форматирование** — Markdown с учётом ограничений MAX (без списков и таблиц).
- **Обход лимитов MAX** — ответы длиннее 4000 символов режутся на части, отправка выдерживает паузу между сообщениями (2 сообщения/сек).
- **Сертификаты** — MAX API использует российский сертификат Минцифры: бот автоматически использует системный CA-бандл вместе с `certs/russian_trusted_root_ca.pem` из проекта.

## Состав проекта

```
max-glm-bot-php/
├── index.php               # публичная точка входа вебхука (её адрес регистрируется в MAX)
├── run.php                 # CLI: polling для cron / бесконечный режим / самопроверка
├── install.php             # установка: окружение, таблицы БД, подписка вебхука, статус
├── config.inc.php.example  # шаблон настроек → скопировать в config.inc.php
├── schema.sql              # SQL-схема (ручной импорт через phpMyAdmin, опционально)
├── .htaccess               # закрывает config, logs, data, test, run.php от веба
├── certs/russian_trusted_root_ca.pem  # корневой сертификат Минцифры для MAX API
├── lib/                    # код: config, logger, db, store (MySQL/файлы), max-api, glm, bot
└── test/                   # smoke-тесты с моками MAX и GLM
```

Данные в MySQL: `maxbot_memory` (история диалогов), `maxbot_stats` (токены по дням), `maxbot_state` (маркер polling, служебные отметки). Префикс меняется в конфиге.

## Требования

- PHP 7.4+ (рекомендуется 8.1–8.3) с расширениями **curl, pdo_mysql, json, mbstring** — на AdminVPS включены по умолчанию; версию PHP выбирают в панели.
- MySQL 5.7+ / MariaDB.
- Домен с HTTPS (для webhook-режима). На AdminVPS SSL/Let's Encrypt включается в разделе доменов бесплатно.

## Шаг 1. Создайте бота в MAX

1. Откройте MAX, в поиске — `@masterbot` (официальный, с галочкой).
2. Отправьте `/create` и следуйте подсказкам (имя, описание).
3. Скопируйте **access_token** — он появится в ответе и в настройках бота (Chat-bots → Настройки).

## Шаг 2. Получите ключ Z.ai

1. Зарегистрируйтесь на [z.ai](https://z.ai) (Open Platform), создайте ключ в разделе **API Keys**.
2. Модель `glm-4.5-flash` — бесплатная; актуальные условия смотрите в личном кабинете.

## Шаг 3. Создайте базу MySQL в панели AdminVPS

1. Панель AdminVPS → **Базы данных** → создать базу и пользователя, выдать права.
2. Запомните: имя базы, имя пользователя, пароль (хост — обычно `localhost`).

## Шаг 4. Загрузите файлы на хостинг

1. Файловый менеджер панели → папка сайта (`public_html` или аналогичная).
2. Рекомендуется отдельная подпапка, например `public_html/maxbot/`, и загрузить туда всё содержимое проекта.
3. Установите права на запись для папок `logs/` и `data/` (775 или 777 в зависимости от настроек хостинга).

## Шаг 5. Настройте config.inc.php

Скопируйте `config.inc.php.example` → `config.inc.php` и заполните:

```php
'max_token' => 'токен из @masterbot',
'zai_key'   => 'ключ Z.ai',
'db' => [
    'name' => 'имя_базы',
    'user' => 'пользователь_базы',
    'pass' => 'пароль_базы',
    // host, port, prefix — обычно менять не нужно
],
'webhook_secret' => 'длинная случайная строка',  // например: openssl rand -hex 24
'setup_key'      => 'случайная строка',          // доступ к install.php из веба
```

Остальные параметры (модель, характер бота `system_prompt`, память, белый список, режим) — в том же файле, с комментариями.

## Шаг 6. Установка и запуск

### Веб-установщик (проще всего)

Откройте `https://ваш-домен/maxbot/install.php?key=<setup_key>`:

1. Проверьте таблицу **Окружение** — все пункты должны быть ✅.
2. Нажмите **«Создать таблицы»** — появятся `maxbot_memory`, `maxbot_stats`, `maxbot_state`.
3. Нажмите **«Зарегистрировать вебхук в MAX»** — URL подставится автоматически (`https://ваш-домен/maxbot/index.php`); секрет возьмётся из конфига.
4. Напишите боту в MAX — он должен ответить приветствием.

Через SSH то же самое: `php install.php check | tables | subscribe <url> | webhook | status | log [N] | cron`
(`webhook` — статус подписки в MAX, `log` — последние строки лога).

Если бот молчит: откройте install.php — разделы **«Текущая подписка в MAX»** и **«Лог бота»** сразу покажут, доходят ли события и в чём ошибка.

После установки удалите `install.php` или оставьте — он закрыт ключом `setup_key`.

### Альтернатива: cron-polling (без вебхука)

Если не хотите настраивать SSL или домен занят другим сайтом — в config.inc.php ничего менять не нужно, просто не регистрируйте вебхук и настройте cron:

1. Панель AdminVPS → **Планировщик (Cron)** → новое задание каждую минуту:
   ```
   php -f /путь/к/сайту/maxbot/run.php -- --once
   ```
   (точный путь к PHP и скрипту подскажет панель; вариант строки для crontab: `* * * * * php -f /var/www/…/maxbot/run.php -- --once >> /dev/null 2>&1`)
2. Скрипт сам снимает старую подписку вебхука, работает до 55 секунд и завершается; повторные запуски не пересекаются (блокировка через `GET_LOCK`).

> ⚠️ Не смешивайте режимы: если вебхук зарегистрирован — cron не запускайте, и наоборот. При смене режима перезапуск не нужен: `run.php` снимает подписку при старте.

## Основные настройки (config.inc.php)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `max_token` / `zai_key` | — | Токены MAX и Z.ai (**обязательно**) |
| `model` | `glm-4.5-flash` | Модель GLM |
| `system_prompt` | дружелюбный ассистент | Характер бота |
| `glm_thinking` | `disabled` | `disabled`/`enabled`/`auto` |
| `mode` | `webhook` | Режим подключения (справочно для документации) |
| `webhook_secret` | — | Секрет заголовка `X-Max-Bot-Api-Secret` |
| `memory_limit` | `12` | Сколько сообщений диалога помнить |
| `chat_whitelist` | `[]` | Разрешённые `chat_id`; пусто — все чаты |
| `group_trigger` | `all` | В группах: `all` или `mentions` (только @упоминание) |
| `send_format` | `markdown` | `markdown`/`html`/`plain` |
| `storage` | `mysql` | `mysql` или `files` (data/*.json) |
| `db` | — | Доступ к MySQL (**обязательно** для mysql) |
| `ca_bundle` | `''` | Свой CA-бандл (пусто — авто: система + certs/) |

Переменные окружения `MAXBOT_*` переопределяют любые значения (например, `MAXBOT_MODEL=glm-4.6`) — удобно для тестов.

## Тесты

```bash
php test/smoke.php                      # фазы polling + webhook (файловое хранилище)
MAXBOT_TEST_MYSQL=1 \
MAXBOT_DB_SOCKET=/tmp/mysql.sock \
MAXBOT_DB_NAME=maxbot_test \
MAXBOT_DB_USER=root \
MAXBOT_DB_PASS= \
php test/smoke.php                      # + фаза реальной MySQL
```

Поднимает моки MAX и GLM, проверяет: приветствия, команды, память, `/reset`, разбивку длинных ответов, белый список, секрет вебхука, запись в MySQL (29 проверок). В песочнице тесты прогонялись на PHP 8.4 и MariaDB 11.4 — все пройдены; также проверена связь с реальными `platform-api2.max.ru` и `api.z.ai` (обе отвечают корректными ошибками на фейковый токен).

## Лимиты MAX

- Текст сообщения ≤ 4000 символов — бот режет ответы по словам на части ≤ 3900.
- ≤ 2 сообщений/сек на чат — пауза 600 мс между частями.
- Markdown MAX: `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `++подчёркнутый++`, `` `код` ``, `> цитата`, `[ссылка](url)`, `# заголовок`; **списки и таблицы не поддерживаются** — промпт бота запрещает их модели.
- Вебхук: MAX ждёт HTTP 200 ≤ 30 секунд (бот отвечает мгновенно), при сбоях ретраит доставку до 10 раз; после 8 часов неудач подписка снимается — перерегистрируйте в install.php.

## Устранение неполадок

| Симптом | Что делать |
|---|---|
| `MAX API 401 … Invalid access_token` | Неверный `max_token` — проверьте токен из @masterbot |
| `GLM HTTP 401` | Неверный `zai_key` |
| `GLM HTTP 429` | Квота Z.ai — бот сам ретраит раз; при повторении подождите |
| `GLM HTTP 400` про `thinking` | `glm_thinking` → `auto` |
| `SSL certificate problem` при обращении к MAX | Убедитесь, что папка `certs/` с файлом `russian_trusted_root_ca.pem` загружена на хостинг; при необходимости задайте `ca_bundle` вручную |
| `SQLSTATE[…] Access denied` | Ошибки `db.*` в config.inc.php |
| **Написал боту — тишина** | Порядок: 1) install.php?key=… → раздел 1 «Окружение» — всё ✅? 2) раздел 3 «Текущая подписка в MAX» — есть? Если нет — кнопка «Зарегистрировать вебхук». 3) раздел 5 «Лог бота»: пусто → события не доходят (вебхук не тот URL / домен недоступен по HTTPS); есть строки «Сообщение из чата…» → причина видна в самой ошибке. 4) Если настраивали cron с run.php — он удаляет вебхук при каждом запуске: оставьте ОДИН режим (см. строку ниже) |
| Cron (run.php) и вебхук конфликтуют | run.php при запуске снимает подписку вебхука — режимы нельзя смешивать. Хотите webhook — уберите задание cron; хотите polling — не регистрируйте вебхук |
| События не доходят до бота (лог пуст) | Проверьте: URL вебхука заканчивается на `/index.php`? Домен открывается в браузере по https:// без предупреждения о сертификате (Let's Encrypt включён в панели)? Hosting не блокирует POST (проверьте curl -X POST -d '{}' https://домен/maxbot/index.php — должен вернуть `{"success":false}` с 403 из-за секрета, но не 500) |
| Хостинг режет запись файлов (open_basedir) | Задайте `log_file` внутри разрешённой папки сайта; лог и `data/` должны быть записуемыми |
| Звёздочки `**` в ответах | `send_format` → `plain` |
| Белый экран / 500 | Включите отображение ошибок в панели или смотрите error_log хостинга; чаще всего — права на `logs/`, `data/` или старая версия PHP |

## Безопасность

- `config.inc.php`, `logs/`, `data/`, `test/`, `lib/`, `run.php` закрыты `.htaccess` — для nginx-only окружения держите их вне публичной папки.
- Не публикуйте `config.inc.php` (там токены MAX и Z.ai); права 600 в панели.
- `setup_key` и `webhook_secret` — обязательные случайные строки в продакшене.
- Корневой сертификат Минцифры из `certs/` — публичный официальный файл (gu-st.ru); его SHA-256:
  `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`
  При желании проверьте командой `openssl x509 -in certs/russian_trusted_root_ca.pem -fingerprint -sha256 -noout` или замените файл скачанным самостоятельно.
