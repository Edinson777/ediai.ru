# Аудит и план развития сайта «База промптов для ИИ»

**Проанализированы страницы:**
- `prompt-base.html` — «База промптов для ИИ» (71 промпт: изображения, тексты, Qwen, основы), 118 КБ (≈36 КБ gzip)
- `photo-edit-prompts.html` — «Переделка фото нейросетью» (54 промпта), 81 КБ (≈23 КБ gzip)

**Дата аудита:** ноябрь 2026. Всего на сайте: 125 промптов, 2 страницы, 0 внешних зависимостей.

---

## 0. Короткое резюме (что хорошо / что критично)

### Сильные стороны (оставить как есть)
- Чистый, современный тёмный дизайн: aurora-градиенты, glassmorphism-панель, pill-табы — всё в тренде 2026.
- Отличная скорость: один самодостаточный файл, системные шрифты, ноль внешних запросов, нет изображений. LCP фактически мгновенный, CLS ≈ 0.
- Продуманный UX-каркас: живой поиск с debounce (150 мс), авто-раскрытие карточек при поиске, горячая клавиша `/`, копирование в буфер с fallback для старых браузеров, тост, empty state, кнопка «наверх», `aria-expanded` + управление с клавиатуры на карточках.
- Контент качественный: источники, пометки совместимости с моделями, советы-`tip`, этическая памятка.
- Данные отделены от логики (массив `PROMPTS`) — сайт легко расширять.

### Критичные проблемы (порядок исправления — в разделе 2)
1. **SEO = 0.** Весь контент рендерится JavaScript'ом; нет meta description, OG-тегов, canonical, JSON-LD, favicon. Для Яндекса (основной поисковик русскоязычной аудитории) клиентский рендеринг — серьёзный риск: 125 промптов для него фактически не существуют.
2. **Нет ни одного визуального примера.** На странице про переделку фото пользователь не видит результат ни одного промпта. Для этой ниши «до/после» — главный аргумент.
3. **Мобильная липкая панель съедает до 40% экрана**: поиск + 6 табов в 2–3 ряда + чипсы в 2 ряда + строка результатов ≈ 250–280 px высоты.
4. **Доступность**: контраст мелкого текста ниже WCAG AA (3.5–3.7:1 при норме 4.5:1), поиск без `aria-label`, тост без `aria-live`, анимации без `prefers-reduced-motion`.
5. **Дублирование кода**: ~450 строк одинаковых CSS/JS на обеих страницах, уже разошлись в ~120 строках (max-height карточки 300 vs 260 px, размеры шрифтов). Правки приходится вносить дважды.
6. **Нет deep linking**: состояние (категория/поиск/карточка) не сохраняется в URL — нельзя поделиться ссылкой на подборку, кнопка «назад» не работает внутри фильтров.

### 1.2. Удобство использования — конкретные находки

**Что работает хорошо:** авто-раскрытие карточек при поиске; debounce; «Развернуть все» учитывает текущий фильтр; fallback-копирование через `execCommand` и выделение текста; подсветка `[плейсхолдеров]` оранжевым; пустое состояние поиска;键盘-доступ карточек (Enter/Space).

**Проблемы (по убыванию важности):**

1. **Мобильная панель фильтров** (см. выше) — на телефоне контент начинается почти с середины экрана. Решение: табы в один горизонтально скроллящийся ряд, чипсы скрывать за кнопку «Фильтры».
2. **Кнопка «Свернуть все» молча очищает поиск** — неожиданная связка двух действий, пользователь теряет запрос. Разделить: «свернуть» ≠ «сбросить поиск».
3. **Кнопка «Копировать» перекрывает первую строку промпта** (absolute в углу `pre`) — при длинном тексте начало читается из-под неё. Добавить `padding-top` у `pre` или вынести кнопку в шапку карточки.
4. **Вложенный скролл**: промпт в `pre` с `max-height: 260–300px` — на мобильном «скролл в скролле» раздражает. Лучше ограничивать высоту только на десктопе или показывать «развернуть текст».
5. **Нет состояния в URL** — нельзя дать ссылку «все промпты про реставрацию» или вернуться назад после смены таба.
6. **Нет избранного** — пользователь, вернувшийся через неделю, начинает заново. `localStorage`-закладки решают это за ~30 строк кода.
7. **Поиск не подсвечивает найденное** в тексте промпта и не прощает опечаток («акврель» → ничего). Минимум — подсветка совпадений `<mark>`.
8. **Страница сама отправляет пользователя «попросить чат-бота перевести промпт на английский»** — это трение, которое можно убрать кнопкой RU/EN (переводы заготовить статически).
9. Контраст: `#5d6a82` (футер, строка результатов) — 3.55:1; `#64748f` (теги, sub-name) — 3.67:1 на фоне карточек. Оба ниже 4.5:1 (WCAG AA) для мелкого текста. Поднять до `#8b97ad` / `#94a3b8`.
10. Нет `aria-label` у поиска (placeholder — не замена), тост не объявляется скринридерами (`aria-live="polite"`), нет skip-link.

### 1.3. Скорость загрузки

**Текущее состояние — отличное**, это конкурентное преимущество, его важно не сломать:
- 23–36 КБ gzip на страницу, 0 внешних запросов, 0 шрифтов, 0 картинок → LCP < 1 c на любом соединении, CLS ≈ 0, INP в норме (125 карточек перерисовываются мгновенно).
- Единственный потенциальный тормоз — `backdrop-filter` на слабых Android; приемлемо.

**Правила, чтобы скорость не деградировала при развитии:**
- Изображения примеров: AVIF/WebP, `loading="lazy"`, явные `width/height` (иначе появится CLS), `srcset` для мобилы, целевой вес ≤ 60–100 КБ на пару «до/после».
- Хостинг со сжатием brotli/gzip и CDN (Cloudflare Pages / Netlify / GitHub Pages — бесплатно).
- Общий `style.css` + `data.js` + `app.js` вместо дублей в каждой странице → кэш работает между страницами, повторные визиты почти бесплатны.
- Не тянуть React/Vue «на 125 карточек» — ванильный JS здесь быстрее любого фреймворка. Если нужна генерация страниц — статическая сборка (Astro/Eleventy), а не клиентский фреймворк.
- Ориентиры Core Web Vitals: LCP < 2.0 c, INP < 200 мс, CLS < 0.05 — при выполнении правил выше достижимы легко.

## 2. Что исправить в первую очередь (пошагово, с обоснованием)

### P0 — на этой неделе (дешёво, эффект сразу)

**Шаг 1. Мета-теги и превью для соцсетей.**
*Зачем:* сейчас при отправке ссылки в Telegram/VK/WhatsApp она выглядит голой (нет картинки, заголовка, описания) — теряется кликабельность, а шеринг в мессенджерах для такого сайта — главный канал роста. Поисковики без description показывают произвольный текст сниппета.

```html
<meta name="description" content="54 готовых промпта для переделки фото нейросетью: стили (акварель, аниме, киберпанк), фотосессии, замена одежды и фона, реставрация старых снимков. Копируйте и вставляйте свои данные.">
<meta property="og:type" content="website">
<meta property="og:title" content="Переделка фото нейросетью — 54 промпта">
<meta property="og:description" content="Стили, виртуальные фотосессии, реставрация — готовые промпты с кнопкой «копировать».">
<meta property="og:image" content="https://ВАШ-ДОМЕН/og-photo-edit.png">
<meta property="og:locale" content="ru_RU">
<meta name="twitter:card" content="summary_large_image">
<link rel="canonical" href="https://ВАШ-ДОМЕН/photo-edit-prompts.html">
<meta name="theme-color" content="#0b0e14">
<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 100 100'><text y='.9em' font-size='90'>⚡</text></svg>">
```

**Шаг 2. Мобильная панель фильтров.**
*Зачем:* 60–80% трафика таких сайтов — мобильный; сейчас панель съедает до 40% экрана и отталкивает первого впечатления.

```css
@media (max-width:640px){
  .tabs{flex-wrap:nowrap;overflow-x:auto;scrollbar-width:none;-webkit-overflow-scrolling:touch}
  .tabs::-webkit-scrollbar{display:none}
  .chips{display:none}            /* показывать по кнопке «Фильтры ⚙» */
  .chips.open{display:flex}
  .search-row{margin-bottom:8px}
  #search{padding:9px 14px 9px 38px;font-size:16px} /* 16px — иначе iOS зумит input */
}
```
Плюс кнопка-тумблер чипсов и уменьшение вертикальных отступов. Важно: `font-size:16px` у инпута убирает авто-зум iOS.

**Шаг 3. Контент, видимый без JS (SEO-фундамент).**
*Зачем:* все 125 промптов сейчас внутри `<script>` — Яндекс/Google увидят почти пустую страницу. Это главная причина, по которой сайт не получит поисковый трафик.
Минимальное решение без переписывания: добавить статический блок (виден поисковикам и пользователям с выключенным JS), а JS-приложение оставить как есть:

```html
<noscript>
  <style>#grid{display:none}</style>
  <section class="wrap"><!-- статический список: H2-подразделы + H3-заголовки промптов + текст промптов --></section>
</noscript>
```
Правильное решение (шаг развития, не срочный) — статическая генерация тех же страниц из общего `data.js` (простой Node-скрипт или Astro): HTML содержит все карточки сразу, а JS только добавляет интерактив. Тогда не нужен и `<noscript>`.

**Шаг 4. Доступность — минимальный набор.**
*Зачем:* читаемость для всех пользователей (контраст!), доступность для людей со скринридерами, и это учитывают поисковики (Core Web Vitals + качество страницы).

```html
<input id="search" aria-label="Поиск по промптам" ...>
<div id="toast" role="status" aria-live="polite"></div>
```
```css
/* контраст: заменить */
#5d6a82 → #8b97ad  (футер, results-line)
#64748f → #94a3b8  (теги, sub-name, chev)

@media (prefers-reduced-motion: reduce){
  html{scroll-behavior:auto}
  *,*::before,*::after{transition-duration:.01ms !important;animation-duration:.01ms !important}
}
```
Карточки в идеале перевести на нативные `<details>/<summary>` — бесплатная доступность и работа без JS.

**Шаг 5. Аналитика.**
*Зачем:* без неё развитие вслепую. Нужно знать: какие промпты копируют чаще (событие на кнопку «Копировать» с названием промпта), откуда трафик, что ищут в строке поиска (сохранять запросы с 0 результатов — это готовый список новых промптов!). Яндекс.Метрика бесплатна; событие «copy» добавляется одной строкой в существующий обработчик.

### P1 — следующие 2–3 недели

**Шаг 6. Deep linking (состояние в URL).**
*Зачем:* шеринг подборок («вот тебе все промпты про реставрацию» — сильнейший механизм роста в Telegram), рабочая кнопка «назад», индексация фильтров. Реализация: `location.hash = #cat=restore&q=лицо`, чтение хэша при загрузке, `history.replaceState` при изменениях. ~40 строк кода.

**Шаг 7. Разделить «Свернуть все» и сброс поиска; не перекрывать кнопкой «Копировать» текст; подсветка совпадений в поиске.**
*Зачем:* мелкие UX-раздражители, которые суммарно формируют ощущение «недоделанности». Дёшево исправляются.

**Шаг 8. Переключатель RU/EN для промптов переделки фото.**
*Зачем:* страница сама признаёт, что для западных моделей промпт надо переводить. Две кнопки («Копировать RU» / «EN») с заготовленными переводами убирают целый шаг пользователя. Это уникальное преимущество перед конкурентами — почти ни одна русская библиотека так не делает.

**Шаг 9. Вынести общие CSS/JS в отдельные файлы.**
*Зачем:* код уже разошёлся в ~120 строках; каждый багfix нужно делать дважды, новые страницы будут копипастой. Общая `style.css`, общий `app.js`, данные — в `data-base.js` и `data-photo.js`. Кэш браузера делает повторные визиты мгновенными.

### P2 — в рамках первого месяца

**Шаг 10. Визуальные примеры «до/после»** — см. раздел 4 (это уже развитие, но начинать собирать примеры стоит сразу: сгенерировать по 1–2 примера на топ-20 промптов).
*Зачем:* конверсия «прочитал → попробовал» на странице про редактирование фото без примеров в разы ниже. Ожидание пользователя: «покажите, что получится».

**Шаг 11. Избранное (localStorage)** — звёздочка на карточке + фильтр «Избранное» + счётчик. *Зачем:* возвращаемость; пользователь собирает «свой» набор и приходит за ним.

**Шаг 12. Светлая тема по `prefers-color-scheme` + styles для печати.** *Зачем:* часть аудитории читает при свете/печатает шпаргалки. Тёмная — по умолчанию и принудительно, светлая — как опция системы.

**Шаг 13. JSON-LD разметка** (`WebSite`, `ItemList`, на будущих статьях — `FAQPage`, `HowTo`) + `robots.txt` + `sitemap.xml` + регистрация в Яндекс.Вебмастере и Google Search Console. *Зачем:* расширенные сниппеты, попадание в AI-ответы (AEO/GEO), корректная индексация.

## 3. Как организовать сайт: одна, две или несколько страниц?

### Рекомендация: **несколько страниц (малый статический сайт)**, а не одна и не две

Текущие две страницы — «склад всего» без главного входа. `prompt-base.html` играет роль главной по факту (на неё ведёт back-link), но она называется «База промптов» и содержит 4 разные сущности. Проблемы двухстраничной схемы:
- каждая страница — одна SEO-страница под один кластер запросов, а запросов минимум 6–8 разных («промпты для фото», «переделать фото нейросетью», «промпты для текста», «промпты qwen», «промпт для продаж»…);
- 125 карточек грузятся разом, даже если человеку нужны 6 промптов про реставтацию;
- нет места для статей-гайдов, которые и приводят поисковый трафик.

### Целевая структура

```
/                     — Главная-хаб (bento-grid):
                        · крупные плитки разделов с иконкой, описанием, счётчиком
                        · «Новое на сайте» (3–5 свежих промптов)
                        · «Популярное» (по данным аналитики о копированиях)
                        · мини-FAQ + ссылка на Telegram-канал
/photo/               — Переделка фото (текущая photo-edit-prompts.html)
/generate/            — Создание изображений с нуля (cat:"img" из базы)
/texts/               — Тексты: копирайтинг, статьи, соцсети, редактура (cat:"txt")
/qwen/                — Всё про Qwen: Chat, Image, Image-Edit, Coder (cat:"qwen")
/basics/              — Основы промптинга: универсальные формулы (cat:"base")
/guides/              — Статьи-гайды (появятся на этапе 3):
                        «Как бесплатно переделать фото нейросетью»,
                        «Фото на документы с помощью ИИ»,
                        «Реставрация старых фотографий: пошагово»
/prompts/<slug>/      — отдельные страницы ТОП-промптов (позже, под конкретные
                        высокочастотные запросы: «промпт фото на документы»,
                        «промпт раскрасить чб фото»…)
```

**Общие файлы:** `style.css`, `app.js`, `data.js` (единый источник всех 125+ промптов с полем `section`). Все страницы генерируются из одних данных — простой Node-скрипт или Astro/Eleventy (Astro предпочтительнее: контент-коллекции, нулевой JS по умолчанию, идеальные Lighthouse-показатели, бесплатные шаблоны).

**Почему не одна страница (SPA):** убивает SEO (главный бесплатный канал для такой темы), лишает каждую категорию собственного URL под поисковый запрос, заставляет грузить всё сразу.

**Почему не остаться на двух:** сайт упирается в потолок «2 URL = 2 поисковых кластера»; дублированный код продолжает расходиться; некуда класть статьи.

**Компромисс, если сил мало:** сохранить текущие 2 страницы, но (а) сделать из `prompt-base.html` честный хаб с разделением на 4 секции с якорями, (б) внедрить deep-linking, (в) добавить статический контент для SEO. Это 20% усилий и 60% эффекта, но потолок роста остаётся.

**Хостинг:** Cloudflare Pages / Netlify / GitHub Pages — бесплатно, CDN по миру (включая быстрый ответ по РФ через доступные точки), HTTPS из коробки, автодеплой из git-репозитория. Домен — любой .ru/.com (~200–1000 ₽/год).

## 4. Пошаговый план развития сайта

### Этап 1 (недели 1–2): Фундамент
Всё из раздела P0 + домен и хостинг с CDN, `robots.txt`, `sitemap.xml`, Яндекс.Метрика (+ Google Analytics 4 опционально), регистрация в Яндекс.Вебмастере / Google Search Console.
**Результат:** сайт индексируется, ссылки красиво шарятся, есть данные о поведении.

### Этап 2 (недели 2–4): Визуальный контент — «покажите, что получится»
1. Сгенерировать примеры **до/после** для топ-20 промптов страницы «Переделка фото» (начать с самых массовых: хедшот, документы, реставрация, колоризация, акварель, Pixar, замена фона, Paris).
2. Встроить их в карточки: миниатюра-превью на свёрнутой карточке (сейчас свёрнутая карточка — просто текст, глазу не за что зацепиться), при раскрытии — слайдер до/после или пара изображений.
3. Формат: AVIF/WebP ≤ 80 КБ на пару, lazy-loading, фиксированные размеры.
4. Сделать OG-картинки (1200×630) для обеих страниц — скриншот интерфейса с яркой карточкой и заголовком.

**Какая информация нужна пользователю дополнительно (закрывает 80% его вопросов):**
- **Где это делать:** таблица сервисов — название, ссылка, цена/лимиты, доступность из РФ, нужен ли VPN, мобильное приложение. Сейчас «шпаргалка: чем переделывать фото» спрятана внутри карточки промпта — ей место в отдельном видимом блоке/статье.
- **Как подготовить фото:** требования к исходнику (лицо анфас, ровный свет, ≥1024 px, без фильтров и очков) — короткая памятка в начале страницы.
- **Что делать, если не получилось:** FAQ-блок «лицо изменилось / руки с артефактами / надпись поплыла / стиль не применился» — с конкретными фразами-добавками к промпту. Это готовый `FAQPage` JSON-LD и ответ на реальные поисковые запросы.
- **RU/EN версии промптов** (P1, шаг 8).

### Этап 3 (месяц 2): Многопользовательские ценности и SEO-контент
1. Переезд на многостраничную структуру (раздел 3) с общей кодовой базой.
2. 3–5 статей-гайдов в `/guides/` под высокочастотные запросы (каждую иллюстрировать примерами из базы промптов; внутри — ссылки на карточки промптов через deep links). Статьи — основной источник органики: промпты люди ищут точечно, а гайды приводят «холодных» новичков.
3. Промпт-билдер: форма с полями под `[плейсхолдеры]` топ-промптов («город», «эпоха», «что сохранить») → собирает готовый промпт → «Копировать». Начать с 5–10 самых популярных шаблонов.
4. Changelog-блок «Что нового» (дата + новые промпты) — сигнал жизни сайта и пользователям, и поисковикам.

### Этап 4 (месяцы 2–3): Дистрибуция и комьюнити
1. **Telegram-канал** «промпт дня» + кнопка-подписка в шапке; бот, присылающий случайный промпт по команде. Для русскоязычной ниши TG — канал №1.
2. **Форма «предложить промпт»** (Google Forms/Telegram-бот на старте) — контент начинают делать пользователи; с moderation-очередью.
3. Кнопка «Поделиться промптом» (deep link + Web Share API) на каждой карточке.
4. Лёгкая обратная связь на карточке: «сработало 👍 / не сработало 👎» (можно без бэкенда — через бесплатный счётчик или форму) — данные для ранжирования «Популярного» на главной.
5. Избранное + «недавно скопированные» (P2, шаг 11) — возвращаемость без аккаунтов.

### Этап 5 (месяцы 3–6): Расширение и (опционально) монетизация
1. **Новые категории** (по данным аналитики и поисковых запросов с нулём результатов):
   - **Видео-промпты** (Sora 2, Veo 3, Kling, Runway) — самый горячий сегмент 2026, конкурентов в RU-сегменте мало;
   - промпты для учёбы/преподавателей, для HR и резюме, для e-commerce (карточки товаров — частично уже есть);
   - «нейросети для бизнеса»: серия промптов под конкретные профессии.
2. **Английская версия сайта** (i18n) — рынок больше на порядок.
3. PWA: установка на телефон, офлайн-доступ (сайт статический — service worker добавляется почти бесплатно).
4. Монетизация (когда появится трафик ≥ 500–1000 визитов/день): премиум-паки промптов (PDF/Notion), донаты (Boosty/Telegram Stars), партнёрские ссылки на нейросервисы, маленький курс «нейрофотосессия за 30 минут».
5. AEO/GEO: файл `llms.txt` с описанием структуры сайта, последовательная JSON-LD-разметка, четкие ответы «вопрос-ответ» в начале разделов — чтобы ИИ-ассистенты цитировали сайт как источник.

### KPI для проверки гипотез
| Метрика | Где смотреть | Цель на 3 месяца |
|---|---|---|
| Проиндексировано страниц | Яндекс.Вебмастер / GSC | все разделы + гайды |
| Органический трафик | Метрика | первые 100–300 визитов/день к 3-му месяцу |
| Копирований промпта за сессию | событие в Метрике | ≥ 2 (сейчас неизвестно — потому и нужен шаг 5) |
| Запросы с 0 результатов | лог поиска | превращать в новые промпты еженедельно |
| Подписчики TG | канал | 100–300 за квартал при активном шеринге |
| Возвраты в течение 7 дней | Метрика | ≥ 15% — сигнал, что «избранное» работает |
