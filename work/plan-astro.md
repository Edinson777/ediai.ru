# План перехода ediai.ru на Astro

Дата: 2026-11-20 · Ветка: `astro` · Основа: «Структура и стратегия ediai.ru», гл. 7.2–7.3 и дорожная карта (дни 13–30)

## 1. Текущее состояние (что переносим)

- Корень репозитория = готовый сайт. Его собирает `work/site-src/build.py` из единственного
  источника данных `work/site-src/data.json` (211 промптов) + `sources.json`, `config.json`,
  `style.css`, `app.js`, `hub.js`. Выход: 12 HTML-страниц со старыми адресами (`photo.html`, …),
  `robots.txt`, `sitemap.xml`, OG-картинки `og/*.png`, favicon.
- Деплой: FTP-workflow (только ручной запуск, `work/**` исключён) + зеркало GitHub Pages.
- Не трогаем никогда: `z/` (личный склад, в репо), `maxbot/` и `pwa/` (живут на хостинге, в репо
  отсутствуют, закрыты в robots.txt), а также `education/studying-AI.html` (учебный раздел —
  самостоятельная страница, в Astro не переносится, ссылка в навигации сохраняется).
- Сайт не проиндексирован → адреса можно менять без потери позиций; редиректы 301 ставятся
  «на будущее» (по стратегии), но их нельзя откладывать после попадания в индекс.

## 2. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где живёт Astro-проект | `work/site-astro/` | `work/**` уже исключён из FTP-деплоя — исходники не поедут на хостинг |
| Источник данных | `work/site-src/data.json` остаётся единым, Astro импортирует его напрямую | Нет дублей данных; в будущем переехать в `src/content/` (фаза 4) |
| Куда собирается сайт | Astro пишет в `work/site-astro/dist/`, затем `publish.mjs` копирует HTML в корень репо | Astro по умолчанию **очищает** outDir — направлять его в корень нельзя (сотрёт `z/`, `og/`, `.git`) |
| CSS/JS | Импорт как raw-строки (`?raw`) и инлайн в `<style>`/`<script is:inline>` | Сохраняем текущую самодостаточность страниц (0 внешних запросов, SEO без JS-барьера) |
| OG-картинки и favicon | Остаётся Python-генерация из `build.py` (или отдельный `og_gen.py`) | Портировать PIL-код на JS незачем |
| Адреса фазы 1 | `build.format: 'file'` → повторяют текущие (`photo.html`, …) | Шаг 3 плана 7.3: новый стек работает без единого редиректа |
| Адреса фазы 2 | `build.format: 'directory'` → `/prompty/foto/`, `/guides/…` | Целевая URL-конвенция §3.3 стратегии |
| Ветки git | Работа в ветке `astro`; `main` не трогаем до проверки | Сайт и зеркало Pages продолжают жить без изменений |

## 3. Фазы

### Фаза 1 — каркас со старыми адресами (шаги 1–3 плана 7.3; дорожная карта, дни 13–21)

1. Каркас `work/site-astro/`: `package.json`, `astro.config.mjs` (`site: https://ediai.ru`),
   TypeScript-настройки по умолчанию.
2. Общий каркас: `BaseLayout.astro` (head/SEO/OG, JSON-LD, Метрика, GA4 по `ga_id`, РСЯ по
   `ads_block_id`, инлайн CSS/JS, skip-link, футер, toast, noscript-CSS).
3. Компоненты: `Card.astro` (байт-в-байт разметка карточки), пилюли Qwen/DeepSeek, фильтры
   `ftags()`, `grid_html`, чипы/табы/статы.
4. Шаблоны страниц: `Section.astro` (7 разделов), `Index.astro` (главная-хаб с поиском),
   `Know.astro` (start/models/glossary), `Keis.astro` (кейс), `404.astro`.
5. `publish.mjs`: копирует `dist/*.html` в корень; ЗАПРЕТНЫЙ СПИСОК (`z/`, `maxbot/`, `pwa/`,
   `og/`, `education/`, `work/`, `robots.txt`, `sitemap.xml`, favicon) не трогает никогда.
6. Верификация: скрипт сравнения текущих и новых страниц — title/description/canonical,
   нормализованный JSON-LD, число карточек, видимый текст; smoke-тесты jsdom при желании.
7. Деплой — вручную владельцем (FTP-workflow), когда подтверждено.

### Фаза 2 — целевая структура и меню (шаг 4; дни 1–12 дорожной карты)

- `build.format: 'directory'`; роуты: `/prompty/` (карта с фильтрами), `/prompty/{slug}/`
  (6 хабов), `/guides/` + 4 гайда (start→`s-chego-nachat`, basics→`osnovy-promptinga`,
  models→`kakuyu-nejroset-vybrat`, keis→`ii-i-pochta`), `/glossary/`, `/o-proekte/`,
  `/politika-konfidencialnosti/`.
- Меню из 5 пунктов с дропдауном «Промпты/Гайды/Инструменты», хлебные крошки + BreadcrumbList
  на всех страницах, кроме главной; активный раздел подсвечен; мобильный аккордеон.
- Редиректы 301: `.htaccess` (Apache) — список всех старых → новых адресов; вопрос о хостинге
  ниже. Старые `.html` из корня удаляются (индекс пуст).
- `llms.txt` по шаблону приложения; `robots.txt`: явно открыть GPTBot, ClaudeBot, PerplexityBot.
- Футер: категории промптов + служебные ссылки.

### Фаза 3 — автосервисы (шаг 5)

- Pagefind: клиентский поиск по 100+ страницам (индекс собирается после сборки, страница
  результатов `/poisk/`).
- RSS: `@astrojs/rss` — лента гайдов и сценариев.
- `sitemap.xml`: `@astrojs/sitemap` с датами изменения из фронтматтера; `robots.txt` собирается
  в той же цепочке.
- Счётчики промптов в меню и на главной — всегда из `data.json`, руками не правятся.

### Фаза 4 — конвейер публикаций (шаги 2 и 6; дни 22–30)

- Content Collections: `src/content/guides/*.md`, `src/content/scenarios/*.md` — материал =
  Markdown-файл с фронтматтером (title, description, категория, дата, хаб, соседи).
- Шаблон материала: блок-ответ «что на странице» в начале, FAQ-блок, кнопка копирования,
  перелинковка «хаб + 2–4 соседних спока» по чек-листу §5.4 стратегии.
- Первые 2 сценарные страницы: «Нейрофотосессия дома», «ИИ и почта».
- Публикация: sitemap в Вебмастер и GSC, запрос переобхода ключевых страниц.
