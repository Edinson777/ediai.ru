# flint — дневник тренировок (PWA + PHP)

Этап 3: **синхронизация с Яндекс Диском**. Журнал живёт локально (IndexedDB,
офлайн), а его копия — файл `app:/flint-backup.json` в папке приложения на
Диске того аккаунта, который вошёл. Отправка и загрузка — кнопками в карточке
«Синхронизация» плюс автоотправка изменений через 15 секунд; при загрузке
записи сливаются по `updatedAt` (побеждает более новая), так что данные с
телефона и компьютера сходятся без потерь. Операции с Диском идут через
серверную часть (`oauth/disk.php` → `oauth/api.php`): у cloud-api.yandex.net
CORS есть, но токен сознательно не отдаётся в браузер и продлевается сервером.
Этап 2: авторизация через Яндекс ID, refresh-токены в SQLite или MySQL.
Этап 1: PWA-каркас, офлайн-журнал, установка на главный экран, две темы.

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | Единственная страница: форма, история, резервная копия, шапка со входом |
| `manifest.webmanifest` | Манифест PWA: имя Flint, standalone, иконки |
| `service-worker.js` | Офлайн-кэш; запросы в `/oauth/` никогда не кэшируются; при правках поднимать `VERSION` |
| `css/styles.css` | Стили, светлые/тёмные темы, тост-уведомления |
| `js/db.js` | Слой данных IndexedDB (хранилище `workouts`) |
| `js/app.js` | Журнал, экспорт/импорт JSON, темы, установка, статус входа, синхронизация с Диском |
| `icons/` | Иконки: 192/512, maskable 192/512, apple-touch-icon 180 |
| `oauth/config.php` | Конфигурация: автоподстановка Redirect URI, загрузка `secrets.php` |
| `oauth/db.php` | База: SQLite (файл вне корня) **или MySQL** — режим задаётся в `secrets.php`; таблицы `users`, `sessions`, `oauth_states`; cookie-сессии |
| `oauth/http.php` | HTTP-клиент к API Яндекса (curl + запасной вариант) |
| `oauth/login.php` | Вход: одноразовый state (CSRF, 15 мин) → страница согласия Яндекса |
| `oauth/callback.php` | Обмен кода на токены, профиль, сохранение refresh-токена, cookie сессии |
| `oauth/api.php` | JSON API: `me` / `logout` / `refresh` + синхронизация `push` / `pull` / `syncinfo`; токены наружу не отдаются |
| `oauth/disk.php` | Яндекс Диск: продление access-токена, загрузка/скачивание/метаданные `app:/flint-backup.json` |
| `oauth/check.php` | Диагностика (PHP, расширения, база, связь с Яндексом и API Диска) — удалить после проверки |
| `data/.htaccess` | Запасное хранилище закрыто от прямого доступа (403) |

## Где живут секреты и база (важно)

- **Секреты** (`ClientID`/`ClientSecret`) — в файле `secrets.php`, который создаётся
  только на сервере: в папке `flint-data` **рядом с корнем сайта** (вне документного
  корня) или в `oauth/`. Шаблон — `secrets-template.php` из материалов этапа 2.
  В git секреты не попадают, FTP-деплой файл вне корня сайта не трогает.
- **База** — по умолчанию SQLite (`flint.sqlite` в папке `flint-data` вне корня
  сайта; FTP-деплой её не удаляет). Запасной вариант — `flint/data/` (защищена
  `.htaccess`, но при таком варианте деплой может удалить базу — фактическое
  расположение показывает `oauth/check.php`).
- **Если на хостинге нет SQLite** (в `check.php` `pdo_sqlite=НЕТ`) — создайте
  в панели базу MySQL и заполните `FLINT_MYSQL_*` в `secrets.php` (шаблон
  `secrets-template.php`): режим переключится автоматически, таблицы создаются
  при первом обращении.

## Формат записи (согласованный минимальный набор)

```json
{
  "id": "…",
  "date": "2026-11-23",
  "title": "верх — жим",
  "exercises": [
    { "name": "Жим лёжа", "weight": 60, "reps": 8, "sets": 4 }
  ],
  "createdAt": 1763870000000,
  "updatedAt": 1763870000000
}
```

`createdAt`/`updatedAt` — время в мс; в этапе 3 они разруливают слияние копий.

## Синхронизация (этап 3)

- Копия журнала — `app:/flint-backup.json` в папке приложения на Диске вошедшего
  пользователя. Имя файла без uid: `app:/` у каждого аккаунта свой.
- **Отправка** — весь локальный журнал перезаписывает файл на Диске (`overwrite=true`).
- **Загрузка** — записи сливаются в IndexedDB по `id`, побеждает более поздний
  `updatedAt`. Удаления не разносятся: чтобы запись исчезла везде — удалить
  локально и «Отправить на Диск» до того, как другие устройства загрузятся.
- Автоотправка: после каждого изменения ждёт 15 секунд (чтобы уйти устоявшийся
  вариант); при уходе со страницы мелкий журнал досылается сразу, при ошибке
  сети отправка повторяется. Ручные кнопки — в карточке «Синхронизация».
- При первом входе с нового устройства (пустой локальный журнал) копия
  подтягивается с Диска автоматически.

## Деплой

commit → `git push origin main` → Actions → «🚀 Deploy website to FTP» → Run workflow.
После деплоя: создать `secrets.php` (см. инструкцию этапа 2), проверить
`oauth/check.php`, войти в приложение и проверить карточку «Синхронизация»
(см. инструкцию этапа 3). `check.php` после проверки удалить.

Код приложения (js/css/манифест) отдаётся сеть-первая: после деплоя открытые
страницы сами получают свежую пару HTML+JS и один раз перезагружаются. Текущая
сборка — v1.5.1 (видна в консоли браузера и на экране «Ещё»).

## Этап 4 — офлайн-режим и надёжное слияние

- удаления разносятся метками (`deleted`/`deletedAt`): запись исчезает на всех
  устройствах; правка, сделанная после удаления, запись восстанавливает;
- «Отправить на Диск» сначала объединяется с копией на Диске — правки с других
  устройств не затираются; при ошибке чтения копии отправка откладывается;
- офлайн: баннер + полный журнал локально, при возврате сети автоматическая
  отправка накопленных правок (флаг `flint-dirty` переживает закрытие приложения);
- файл на Диске — формат 2 (совместим с этапом 3), сервер принимает оба формата.

Подробности и сценарии проверки — в INSTRUKCIYA-ETAP4.md рядом с архивом.

## Этап 5 — календарь, подходы, библиотека

Ввод перестроен по схеме «календарь → тренировка → упражнение → подход»:

- «Дневники»: месячный календарь с точками тренировок, список за выбранный день;
- тренировка — список упражнений (имя, серая сводка подходов, объём);
- упражнение — таблица подходов с цветной отметкой усилия и серым блоком
  «Прошлое занятие было …» (раскрывается, значения прошлого раза видны);
- подход вводится на отдельном экране: степперы веса/повторов, усилие
  (Разм./Легко/Средне/Тяжело/Предел), комментарий; предзаполняется последним
  подходом или значением с прошлого раза;
- «Справочники» — библиотека упражнений (создание, поиск, переименование,
  удаление); имена в старых тренировках не переписываются (снимок);
- модель данных v3 (подходы), миграция этапов 1–4 выполняется автоматически
  с детерминированными id; файл на Диске — формат 3 (тренировки + библиотека);
- v1.5.1: исправлено зависание запуска после обновления — блокировка повышения
  версии базы другой вкладкой (сообщение-подсказка) и автокоммит транзакции
  миграции в Safari (миграция переписана одной транзакцией без await).

Подробности — в INSTRUKCIYA-ETAP5.md рядом с архивом.
